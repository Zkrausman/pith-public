# Technical Plan: v0.11.0 Fix Token Feedback Loop & Update Analytics

## Problem Statement
The `pith gain` command, designed to show token savings, would output its entire history. When intercepted by Pith (via hooks), this massive output was tracked as a new execution, creating an exponential feedback loop that bloated the telemetry database and consumed excessive tokens in the dashboard.

## Implementation Details

### 1. Gain Command Output Throttling
- **Action:** Limited the output of `pith gain` in `main.go`.
- **Constraint:** Display only the top 20 optimized commands and top 10 discovery opportunities.
- **Goal:** Keep the "intercepted" size small and constant.

### 2. Accurate Token Estimation
- **Action:** Switched from `len(s)` to `utf8.RuneCountInString(s)` in `pkg/runner/runner.go`.
- **Goal:** Ensure accurate token counts in UTF-8 environments.

### 3. Universal Middle-Out Truncation
- **Action:** Updated the `_hook` command in `main.go` to apply `ApplyMiddleOutTruncation` even when no specific parser is matched.
- **Goal:** Prevent massive, unparsed tool outputs from overwhelming the LLM context.

### 4. Cost Basis Update
- **Action:** Updated `pkg/gui/dashboard.html` to use $0.50/M tokens as the savings basis.
- **Goal:** Reflect current market pricing for frontier models (Gemini Flash/Claude Haiku).

### 5. Automated Source Detection
- **Action:** Added `DetectSource()` to `pkg/runner/runner.go` using environment variables.
- **Goal:** Reliable source tracking even without explicit `--source` flags in hooks.

## Evidence of Success
- Verified `pith gain` output is limited.
- Confirmed raw token counts for `pith gain` now only increase by ~1,100 tokens per invocation instead of hundreds of thousands.
- Dashboard cost savings now correctly calculate at the new rate.
